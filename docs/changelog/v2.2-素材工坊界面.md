# v2.2 — 素材工坊并入主菜单

> 一句话：**那个让用户自己抠图的工具，现在和其它窗口长一个样了**，
> 并且成为主菜单的第四个入口，不必再单独开一个 exe 或敲命令行。

## 触发背景

> 把留给用户的自己抠图的那个程序界面也优化一下，和我们其他程序一个画风。
> 或者说直接并入我们这个主菜单吧，作为其中一个功能窗口

两件事：
1. 界面语言统一（和其它窗口同一套设计系统）
2. 从"独立小工具"变成"主程序的一个功能窗口"

## 动手前的事实

旧版 `tools/factory/asset_factory_gui.py`（354 行）功能是完整的，
但样子是完全独立的：

- `QMainWindow` + 系统标题栏，和主程序的**无边框玻璃窗**格格不入
- 三个 `QGroupBox` 蓝灰边框，和暗色面板放在一起像两个软件
- 按钮带 emoji（`📂 打开视频` / `✏️ 画框` / `📸 成功截取`）
- 框选颜色写死 `QColor(0,255,0)` / `QColor(0,255,255)`
- 日志用 `setStyleSheet("color: green")`
- ROI 只按绝对像素存，换分辨率就整体错位

所以不是"美化一下"，是**按现有设计系统重写表现层，逻辑保持不动**。

## 改法

### 1. 界面搬到 `ui/`，tools/ 只留启动器

```
ui/asset_factory.py                  真正的窗口（GlassWindow 子类）
tools/factory/asset_factory_gui.py   6 行 bootstrap + from ui.asset_factory import main
```

为什么搬到 `ui/`：这个窗口已经是主程序的一部分，如果界面还留在 `tools/`，
就得从 tools 反向 import ui 的绘制层，两边样式迟早分叉。
`tools/factory/asset_factory_gui.py` 保留成启动器，是为了让
`python tools/factory/asset_factory_gui.py` 和 `build.bat` 里的 PyInstaller 命令继续可用。

### 2. 主菜单第四个入口

`StartMenu` 加了一个 `open_factory` 信号 + 一行 `NavRow`；
`main.HekiliApp._get_factory_win()` **懒加载**——素材工坊要 `import cv2`
并扫一遍角色目录，启动阶段没必要付这个代价。

入口文案刻意写的是「素材工坊 / 从录像里裁切技能图标，补齐缺的素材」，
而不是「素材工厂」，因为对用户来说它解决的是"我还差几张图"，不是"我要生产素材"。

### 3. 画面：从 `QLabel` 换成自绘画布

旧的 `VideoLabel(QLabel)` 靠 `setPixmap(缩略图)`，然后 `paintEvent` 里再画框。
问题有两个：

- 缩放系数和偏移是**上一次** `set_image` 时算的，窗口一改大小框就错位（没有 `resizeEvent`）
- 每帧都 `QPixmap.fromImage(qimg).scaled(...)`，1440p 原图每帧做一次平滑缩放

新的 `VideoCanvas(QWidget)`：

```
每帧：cv2.resize 到画布尺寸（INTER_AREA）→ QImage 只包指针，不拷贝
坐标：画布 ↔ 原图像素 用 _k = 原图宽/缩略图宽 换算
resize：重建缩略图并重算偏移，框跟着走
```

1440p 缩到 954 宽再做展示，Qt 侧只画 ~50 万像素，
比原来"每帧缩 370 万像素"省了一个数量级。

### 4. 框选标签改成"编号常驻、名称悬停展开"

8 个框里有 3 个挤在血条那一带（回路条、协奏圈彼此很近），
如果每个都画完整标签，必然互相压住。

现在：框内左上角只放一个**编号**（框太小时自动翻到框外），
鼠标移到哪个框上，才把 `[7] 共鸣回路` 这种完整名称展开。
命中检测和绘制共用 `_roi_rects()`，不会出现"看到的位置和点到的位置不一样"。

颜色沿用旧版语义，但走主题：
`1-6`（角色专属）用 `theme.GOLD`，`7-8`（全员通用）用 `theme.CYAN`——
日间主题下自动变成钢蓝和深青，不用单独维护一套色值。

### 5. 顺手修的两个真问题

**换分辨率框会错位**：旧版 ROI 存绝对像素，用 1080p 录像框的区域去裁 1440p 会整体偏，
而用户很难判断是"框错了"还是"分辨率变了"。
现在配置里多记一个 `ref_size`（框选时的视频尺寸），
分辨率变了就按比例重算一次并写回配置，日志里明说发生了什么。

**画质设置不一致时黑屏**：旧版 `QImage(rgb.data, ...)` 直接包 cv2 的缓冲区，
而 cv2 下一帧会复用同一块内存。现在帧数据先落成 `cv2.resize` 的**新数组**再包，
不存在"画到一半被下一帧覆盖"的隐患。

## 实测

- **坐标映射**：画布中心 (487,274) → 原图 (1280,718)，理论 (1280,720)，误差来自缩略图取整
- **裁切**：ROI `119×119` → 存出来的 PNG 就是 `119×119`；连按两次自动编号
  `normal.png` / `normal_2.png`
- **通用目录**：协奏值（第 8 栏）落到 `_general/concerto_energy/concerto.png`，不进角色目录
- **未框选**：只提示"第 4 栏还没框选过"，不崩、不写脏文件
- **分辨率自适应**：基准 1920×1080 遇到 2560×1440，区域 `(2098,1147,119,119)`
  → `(2797,1529,158,158)`，比例 1.333 正确
- **双主题**：夜间/日间都能构造、渲染、运行中切换（缓存底图代数 0→1→2 正常刷新）
- **全窗口冒烟**：启动器 / 设置 / 选择 / 编辑器 / 素材工坊 全部可构造可渲染
- **回归**：89 项测试全绿

## 遗留

- 画布比例固定按"等比居中"处理，21:9 录像上下会有较大留白（不影响框选精度）
- 8 个栏目顺序写死在 `CATEGORIES`，想加第 9 类要同时改 `tools/scaffold.py` 的 `STANDARD_SUBS`
- 视频解码靠 `cv2.VideoCapture`，没有音频、不支持逐帧步进（只能拖进度条）
