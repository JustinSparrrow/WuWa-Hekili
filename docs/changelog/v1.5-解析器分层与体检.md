# v1.5 — 解析器分层重构 + 剧本体检

- **日期**：2026-10-25
- **触发**：作者提出「导演（人话）→ 剧本（程序能懂）→ 演出（窗口）」三层模型，
  指出"演出已完善，但'导演到剧本'的转换（解析器）和'道具'（素材）还很不完整"
- **性质**：地基改造。**不加游戏功能**，但决定了以后加功能有多快、出错有多难查

## 1. 核心判断：容错的三个层次

改之前先定了一条原则，后面所有设计都围着它：

| 层次 | 含义 | 改之前 | 改之后 |
|---|---|---|---|
| **可发现** | 错误必须能被看见 | ❌ 全部静默 | ✅ 报错 + 日志落盘 |
| **可定位** | 错误必须能指到具体位置 | ❌ 只有"解析失败" | ✅ 精确到行列 + 尖号 |
| **可恢复** | 错误不能导致数据丢失 | ❌ 编辑器吞字段 | ⬜ 能力已备（`render`），编辑器尚未接入 |

**这一轮解决的是"可发现"和"可定位"。** 第三条只做了底层能力，UI 还没接。

## 2. 改动前的具体病灶

### 2.1 解析器（`tools/generic_parser.py`）

```python
tokens = self.pattern.findall(text)     # 只返回匹配到的片段
...
if not action_type: continue            # 不认识的直接跳过
```

三个结构性缺陷：

1. **`findall` 丢掉所有不认识的字符**。用户写 `axax`，解析出两个普攻，`x` 消失，
   而且没有任何提示。
2. **没有 span**。所以报错只能说"解析失败"，没法说"第 5 个字符"。
3. **没有中间表示**。JSON 里的 `parallel` / `uncancellable` / `duration_ms`
   无法回写成字符串，于是编辑器重新解析时必然丢失。

### 2.2 素材查找（`utils/asset_manager.py`）

```python
return os.path.join(directory, files[0])    # 变体和关键字都没命中时
```

**这是最隐蔽的一条**：专属目录里找不到匹配的图时，直接拿"目录里排第一张"。
表面看是"有图"，实际可能是完全不相干的动作。而提示只有 `log.debug`，
file handler 是 INFO 级别，**所以连日志里都看不到**。

实测暴露了两个真实问题（就在现有剧本里）：

```
Aemeath 的 execution[forte]: 专属目录没有匹配 forte 的图，取了第一张 skill.png
Lynae 的 skill:             专属目录没有匹配任何关键字的图，取了第一张 skill.png
```

处决显示成了技能图标，一直没人发现。

## 3. 改法

### 3.1 解析器分层：Lexer → Parser → AST → Resolver

```
原始文本
  ↓ Lexer     逐字符扫描，产出带 (行, 列) 的 Token；不认识就报 E001 并继续
Token 流
  ↓ Parser    识别修饰符，产出 Step 列表（含来源位置和原文片段）
AST
  ↓ Resolver  查角色表、补默认值、生成最终 dict；产出 warning
剧本 JSON
```

**为什么不是"给正则打补丁"**：正则只能回答"匹配到了什么"，没法回答"哪里没匹配到"。
位置信息必须来自逐字符扫描，这是能力边界问题，不是实现细节。

关键设计：

- **报错不中断**。遇到坏字符记一条诊断继续走，用户一次能看到所有错误，
  而不是改一个跑一次。
- **Token 带 `raw` 和 span**。这是反向序列化和编辑器高亮的基础。
- **`_line` / `_col` 随动作一起输出**，UI 可以定位到第几步。

### 3.2 新语法（全部可选，旧剧本一个字不用改）

| 语法 | 含义 | 生成的字段 |
|---|---|---|
| `// 注释` `/* 注释 */` | 写轴时做标注 | — |
| `a*3` | 重复三次 | 展开成 3 步 |
| `z&q` | q 与前一步并行 | `parallel: true`（标在后一个动作） |
| `r!` | 不可打断 | `uncancellable: true` |
| `a{620}` | 这步占位 620ms | `duration_ms: 620` |

修饰符顺序不限（`e3+` 和 `e+3` 都认），同一修饰符写两次报 W002。

**`&` 为什么是独立记号而不是后缀**：它的语义是"后一个动作能趁前一个的蓄力先按"，
所以必须作用在**下一个**动作上。如果做成后缀 `z&`，语义就反了。

### 3.3 素材降级可见

`_resolve_icon` 现在返回 `(路径, 来源)`，新增 `explain_icon_path()`：

| 来源代号 | 含义 | 级别 |
|---|---|---|
| `custom` | 剧本指定且命中 | 正常 |
| `exclusive:variant` | 专属目录 + 变体精确命中 | 正常 |
| `exclusive:keyword` | 专属目录 + 关键字命中 | 正常 |
| `exclusive:first` | 专属目录 + **随便拿了第一张** | 警告 |
| `heavy_fallback` | 重击借普攻 | 提示 |
| `general` | 掉到 `AAA_general` 通用库 | 警告 |
| `loose:first` | 角色目录兜底一张 | 警告 |
| `missing` | 完全没有 | 错误 |

降级日志从 `debug` 提到 `warning`（会落盘）。`custom_icon` 指定了却不存在时
也改成 warning，以前是静默换图。

### 3.4 剧本体检工具

`tools/routine_lint.py`，独立运行、不依赖 Qt：

```bash
python tools/routine_lint.py <剧本.json>
python tools/routine_lint.py --all                # 全部剧本
python tools/routine_lint.py <剧本> --ignore-custom  # 检查自动降级路径
python tools/routine_lint.py --assets-only        # 素材覆盖率
```

检查项：

- 顶层必需字段、`team_config` 槽位号连续性、`initial_char_index` 有效性
- 每个动作的 `type` 白名单
- `intro.next_char` 是否在队伍里（**以前这条只会显示 Unknown**）
- `custom_icon` 文件是否真实存在
- `variant` 编号与 `custom_icon` 编号是否打架（**只在目录里确实有更匹配的图时才警告**）
- `duration_ms` 正数且不超过 8 秒
- 素材来源统计 + 可疑项清单
- 武器映射覆盖率（`Character_Occupation.txt` vs 实际角色目录）

**接到加载流程**：`main._preflight()` 在加载剧本前跑一遍，只拦 `error`，
弹窗列前 5 条并问"仍要加载吗"。warning 只写日志——否则玩家会学会无脑点是。
体检自身异常时一律放行：辅助工具的故障不能挡住正常游玩。

## 7. 遗留 / 风险

- **编辑器还没接诊断**。`parse_with_diagnostics` 已经能用，但
  `ui/routine_uploader.py` 仍走 `parse()`，看不到 E001。接线是下一步。
- **`render()` 还没接编辑器**，所以"保存时丢 `parallel`"这个问题**依然存在**。
  能力已经具备（往返测试通过），只是没替换保存逻辑。
- **体检只拦 error**。`exclusive:first`（取错图）被归为 warning，
  不会阻止加载。这是有意的——宁可让玩家玩到，也不要因为一张图拦死。
- `ScriptWriter` 不认识 `custom_icon`，回写时不会输出它。因为黑话语法里
  没有"指定图标"的表达，这个字段本来就只能存在于 JSON 层。
