# v1.2 — 轻按与长按区分

- **日期**：2026-10-25
- **触发**：作者反馈"这个判断重击的逻辑有问题，轻按也会判断为重击，和普通攻击判断重复了"
- **性质**：新增判定规则（**改变手感**，但方向是修 bug）

## 1. 背景

鸣潮里普攻和重击共用同一颗物理键（鼠标左键 / 手柄 B）。v1.0 只按"剧本里写的是什么类型"
来确认，所以：

- 剧本写 `heavy`（重击），玩家**轻点**一下 → 程序认为"重击完成"，推进
- 剧本写 `basic`（普攻），玩家**按住不放** → 程序也认为"普攻完成"，推进

结果是重击格和普攻格在操作上完全一样，重击提示形同虚设。

## 2. 根因

v1.0 的关键代码：

```python
if expected_type == "heavy" and input_action == "basic":
    return True          # 无条件放行
```

以及推进逻辑：

```python
if is_down:
    self.waiting_for_release = True    # 按下：只记"在等这个键松开"
else:
    if self.waiting_for_release:
        self.advance()                 # 松手：直接推进
```

**整个流程里没有"按了多久"这个概念。** 没有时长，就不可能区分轻按和长按。

## 3. 改法

核心原则：**按下只记时刻，松手才算账。**

```
按下  -> 记录 (key, context, timestamp)，不做任何裁决
松手  -> 算出 duration = now - press_time
      -> 取出这一步要求的手势 (mode, threshold)
      -> press_matches(duration, mode, threshold) 决定推不推进
```

### 3.1 新增时长判定函数

新增 `utils/hold_detector.py`：

| 函数 | 作用 |
|---|---|
| `is_long_press(duration, threshold)` | 时长 ≥ 阈值即长按 |
| `is_tap(duration, threshold)` | 时长 < 阈值即轻按 |
| `classify_press(duration, threshold)` | 返回 `"tap"` / `"hold"` |
| `press_matches(duration, mode, threshold, strict_tap)` | 按期望模式裁决 |
| `HoldDetector` | 记录每个键的按下时刻，松手给时长 |

> **注意：该文件已在 v1.3 删除并拆分合并**（测量归 `input_listener.py`，
> 裁决归 `director.py`）。这里保留记录是因为它解释了判定的起源。
> 详见 [v1.3](v1.3-时间轴引擎.md)。

### 3.2 一个必须处理的坑：keydown 自动重复

Windows 对按住不放的键会持续产生 keydown。如果每次 keydown 都重置时间戳，
**长按永远攒不满 0.5s**。

所以 `press()` 是幂等的：同一个键在未松手前重复按下，**只保留第一次的时刻**。

### 3.3 模式来源（`resolve_press_mode`）

| 剧本里的动作 | 要求 |
|---|---|
| `basic` | 必须**轻按**（< 阈值） |
| `heavy` | 必须**长按**（≥ 阈值） |
| `intro` / `dodge` / `jump` | 按下即推进，不看时长 |
| 其它（`skill` / `ult` / `echo`） | 默认不看（`MODE_ANY`），声明了才要求 |

优先级：**显式 `hold` 字段 > 显式 `hold_time` 字段 > 动作类型默认规则**。

```json
{"type": "skill", "desc": "长按技能", "hold": true}
{"type": "skill", "desc": "长按充能", "hold_time": 0.8}
```

> `bool` 是 `int` 的子类，判断时必须**先判 bool 再判数字**，
> 否则 `hold: true` 会被当成"阈值 1 秒"。

### 3.4 黑话新增 `+` 后缀

编辑器是通过重新解析黑话字符串生成剧本的，所以长按标记必须能在字符串里写出来：

```
e+    → {"type": "skill", "hold": true}
e3+   → {"type": "skill", "variant": "3", "hold": true}
```

（`z` 本身就是重击 = 长按语义，不需要 `+`）

### 3.5 判错反馈：闪红

按对了键但手势不对时，不推进，但悬浮窗闪 220ms 红框，并临时把角标改成
「长按」/「轻按」。没有这个反馈，玩家会以为程序卡住了。

配套：正常态角标文字要记忆（`_status_text`），闪完必须还原，
否则普攻格闪一次红之后会永久挂着"轻按"两个字。

### 3.6 配置

```json
"heavy_hold_time": 0.5,      // 长按阈值
"strict_tap_check": true     // 期望普攻时按住太久，是否判为"打出重击"而不推进
```

> `strict_tap_check = false` 时只卡长按、不卡轻按上限。
> 适合习惯"按住攻击键连续普攻"的玩家。

## 6. 遗留 / 风险

- **0.5s 这个阈值是估的**。不同人手速差别大，实机觉得重击难出就调到 0.35~0.4。
- **编辑器会丢手写字段**：`hold` / `hold_time` 是解析产物，进编辑器重新解析会丢。
  想保留必须用 `+` 语法写。
- 这时还没有"时间轴"概念——松手推进是**立即**的，所以按住普攻时若节奏对不上，
  会出现"按了没反应"或"一下推好几格"的问题。这是 v1.3 要解决的。
