# v1.3 — 时间轴引擎（预输入 / 连按 / 并行双轨）

- **日期**：2026-10-25
- **触发**：作者提出三个实际手感问题，认为这是"从可有可无变金凤凰"的关键
- **性质**：核心架构升级，`Director` 从"事件驱动"变成"事件 + 时间轴驱动"

## 1. 三个痛点的原始形态

| # | 现象 | 作者的描述 |
|---|---|---|
| 1 | 蓄力中无法同时放声骸 | "同一时间可以干两件事情按两个键，我们单一的逻辑实现不了" |
| 2 | 预输入空转 | "没打技能前提前按，程序空转了但实际没打出技能" |
| 3 | 连按跑飞 | "角色有施法动画，动画结束前按多少下都是打一下，但我们的程序会一直跑" |

## 2. 技术路线调研（结论先行）

| 方案 | 结论 |
|---|---|
| **读内存** | **否决。** 鸣潮由腾讯 ACE 内核驱动保护，检测内存读取与进程注入，还做"技能释放间隔是否符合动画帧率"的行为分析；用户协议保留扫描内存、封禁设备的权利 |
| **官方插件接口** | **不存在。** 只开放 BBS/抽卡记录这类账号侧 HTTP 接口，没有实时战斗状态。Hekili 能用是因为暴雪给了 Addon API，鸣潮没有这个前提 |
| **视觉识别** | **可行但要付代价。** 开源项目走 WGC 截图 + YOLO/OCR，明确不读内存。代价是常驻 30fps 截图与推理、对分辨率与画面滤镜敏感、UI 改版即失效 |

**关键判断：这三个痛点本质上都不需要知道游戏状态。**

- 预输入空转 → 不是"不知道技能有没有出来"，是**程序把按键当成了施法**
- 连按跑飞 → 同上，是**缺少"动作占位时间"的概念**
- 蓄力+声骸 → 是**剧本表达能力**问题，不是感知问题

所以解法是在程序内部补一条**时间轴**，而不是去读游戏。
视觉识别应该作为 v2.0 的可选闭环校验（确认 CD 真的动了），**不是前提**。

## 3. 核心模型

`Director` 新增四个状态：

```
剧本指针  step_index        当前该做哪一步
时间闸门  _gate_until       这一步动作"占用"到什么时候
输入缓冲  _buffer           闸门关着时收到的、键名正确的输入
并行集合  _ahead_done       已被"提前完成"的未来步（相对当前指针的偏移）
```

一次按键的完整旅程：

```
松手 --> 键名对得上当前步？
          ├─ 手势（轻按/长按）也对
          │    ├─ 闸门已开  -> 直接推进
          │    └─ 闸门未开  -> 压进缓冲，等闸门开     ← 预输入
          └─ 对不上当前步 -> 是蓄力中可插入的动作？是就提前完成它  ← 并行
```

### 3.1 预输入：为什么能治"空转"

缓冲项有寿命（`input_buffer_ms`，初始 300ms，v1.3 末调到 250ms）。
闸门打开那一刻：

- 缓冲里那一下**还在寿命内** → 兑现，推进
- 已经**超过寿命** → 说明玩家按得太早、游戏早就丢弃了 → **不推进**，提示留在原格

这是关键设计：没有任何时间轴的程序，"空转"的原因是它把按键无条件当成施法。
有了寿命判定，程序第一次能表达"这一下不算数"。

### 3.2 连按保护：为什么要合并

同一动作在缓冲里**合并成一条**并刷新时间戳。狂按 5 下，闸门开时只消耗 1 次。
实测狂按 6 下只推进 1 格。

### 3.3 并行双轨：独立小窗

> **这一层在 v1.3 内迭代了两次，最终形态如下。**

初版是在主队列的那一格上加"可同时"角标，作者反馈"效果不是很满意"——
要求做成**主窗上方多一个窗口，明确表示这是两条时间线**。最终：

```
┌──────────────────────────────┐   ← 并行轨小窗（青色描边）
│ [声骸图标]  并行轨 · 可同时    │      位置：主窗左上方 (主窗x+34, 主窗y-62)
│ [Q键]       声骸·蓄力中        │
└──────────────────────────────┘
┌──────────────────────────────┐   ← 主悬浮窗
│ [历史] [🔶重击·长按] [声骸] [跳跃] │
└──────────────────────────────┘
```

实现要点：

- **为什么用独立窗口**：主窗是固定 400×150 的槽位布局，滑入/滑出全靠 geometry 算坐标。
  塞第二行会把布局和动画一起搅乱，且那块空白要一直占着。独立窗口只在有支线时出现。
- **鼠标穿透**：用 `WindowTransparentForInput`（Windows 映射成 `WS_EX_TRANSPARENT`）。
  只设 `WA_TransparentForMouseEvents` 对顶层窗口**无效**，会挡住游戏点击。
- **跟随**：它不能单独拖动，挂主窗 `moveEvent` 跟着走。
- **懒创建**：普通轴连这个窗口都不创建，`parallel_win` 一直是 `None`；
  关主窗时 `deleteLater`，不留残余顶层窗口。
- 主队列那一格**只留青色边框**，文字只在小窗写，避免两处重复。

### 3.4 第二条时间轴按需启用

加载剧本时扫一遍，没有任何可并行处就**完全跳过这套逻辑**：

```python
self._has_parallel = self._detect_parallel(opener_script, loop_script)
```

`False` 时 `_find_parallel_target()` 第一行直接 `return 0`，不产生任何向后探测开销。
判定依据：某步显式 `"parallel": true`，或相邻类型落在 `AUTO_PARALLEL_PAIRS`。
**要检查"启动轴最后一步 → 循环轴第一步"这个跨界处**，否则跨轴并行会漏。

日志会明确写：
```
剧本含可并行动作，启用第二条时间轴（并行轨）
剧本无并行动作，跳过第二条时间轴
```

### 3.5 并行资格：从"类型规律"改为"剧本显式声明"

初版用全局 `AUTO_PARALLEL_PAIRS = {("heavy", "echo")}`，结果**莫宁和爱弥斯的重击
接声骸也被当成可并行**。作者指出只有琳奈能这么做。

这是设计错误：**"蓄力中放声骸"是角色特性，不是动作类型规律。**
改成必须由剧本那一步显式写 `"parallel": true`，`timing.auto_parallel` 默认为 `[]`。

实测四处差别：

```
启动轴 第14步 Mornye heavy -> 并行小窗: 无
启动轴 第25步 Lynae  heavy -> 并行小窗: 声骸·蓄力中
循环轴 第 6步 Mornye heavy -> 并行小窗: 无
循环轴 第17步 Lynae  heavy -> 并行小窗: 声骸·蓄力中
```

## 4. 顺带修的 bug：跨轴预览错角色

**现象**：启动轴最后一步时，后面两格全显示成"普攻"图标，按一下才瞬间变对。

**根因**：

```python
idx = (self.step_index + offset) % total_steps   # total_steps 是「当前剧本」长度
```

启动轴走到末尾时，`+1`/`+2` 取模**绕回启动轴开头**——而启动轴开头正好是 `爱aaaa`。

**修法**：新增 `_peek_action(offset)`，按**真实播放顺序**取第 N 步——跨过
启动轴→循环轴边界，循环轴内部才取模。预览和并行探测都用它，两处逻辑不再分叉。

验证（启动轴 49 步）：

```
启动轴第46步 -> 普攻 | 普攻 | 普攻
启动轴第47步 -> 普攻 | 普攻 | 切-Mornye      ← 已接到循环轴
启动轴第48步 -> 普攻 | 切-Mornye | 解放2      ← 修好了
```

## 5. 合并 `hold_detector.py`

作者反馈"这个文件只是用来实现一个函数，单独独立出来有点多余"。合并时**不是简单搬移**，
而是把两件事分开：

| 职责 | 新位置 |
|---|---|
| **测量**（按住多久） | `utils/input_listener.py`，`_press_start` 记时刻，信号变 `action_detected(str, bool, float)` |
| **裁决**（这个时长算不算数） | `core/preset/director.py` 模块级：`is_long_press` / `is_tap` / `press_matches` / `MODE_*` |

这样做的实际好处：时间戳在**监听线程现场**追加，不再受主线程卡顿污染。
附带修掉两个输入层老问题：按住不放的 keydown 自动重复只上报一次；
十字键 hat 回中时补发"松手"（以前只有 down 没有 up）。

## 6. 角色级时长覆盖

`timing.character_durations`，只写和全局不同的项：

```json
"character_durations": { "Lynae": { "heavy": 780 } }
```

优先级：**剧本单步 `duration_ms` > `character_durations[角色][类型]` > `durations_ms[类型]`**

> **`durations_ms` 不是游戏数据，是手感参数。**
> 不必等于真实帧数，只要和手感对得上：提示**慢半拍**就调小，**抢在前面**就调大。

## 9. 遗留 / 风险

- **`_shift_ahead()` 的过滤条件踩过坑**：必须 `offset >= 1`（`1→0` 表示"轮到时跳过"），
  写成 `>1` 会把提前完成的步重复执行。
- **`parallel: true` 会让那一步永远可并行**（只要前一步是长按态）。
  如果以后要"只有蓄力中可并行、普通重击不可"，得等角色 profile 机制。
- **剧本手写的 `parallel` 进编辑器重新解析会丢**，见 v1.5 待办。
- 本版闸门对**所有**动作生效，会在换键时造成不必要等待 → 见 [v1.4](v1.4-同键缓冲规则.md)。
