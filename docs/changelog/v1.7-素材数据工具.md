# v1.7 — 素材数据工具：wiki 爬虫重写

- **日期**：2026-10-25
- **触发**：作者自己裁图、抄角色数据的工作量太大，想从维基批量获取，
  但之前那版爬虫跑不通；同时问"utils 和 core 功能是否一样、能否合并"
- **性质**：工具补齐 + 数据补齐。核心代码零改动，89 项测试全绿

## 1. 先回答：core 和 utils 该不该合并

**不该，而且它们本来就不是平级的两堆代码——`core/director.py` 自己就
`from utils.config_manager import config`，是"规则"依赖"能力"。**

判据是三个问题，全"是"才放 `core`：

1. 它描述的是**规则**吗？（该不该推进 / 这串字符怎么解 / 什么算长按）
2. 去掉界面和磁盘，它还能工作吗？
3. 只靠传入参数，能写单元测试吗？

对照：

| 文件 | 放哪 | 为什么 |
|---|---|---|
| `director.py` | core | 规则；IO 全靠注入（clock / asset_mgr）；可单测 |
| `script_parser.py` | core | 纯标准库，输入字符串输出 dict，零依赖 |
| `asset_manager.py` | utils | 要 `os.listdir` 扫磁盘 |
| `input_listener.py` | utils | 要 QThread + 键盘/手柄/鼠标外设 |
| `config_manager.py` | utils | 要读写 `config.json` |

合并的代价很具体：`script_parser` 这种零依赖模块会被迫和磁盘 IO 绑在一起，
以后想单独测它，得先准备 `config.json` 和一堆素材目录。
另外 `core` 现在明确"不 import PySide6"，合并后这个约束就守不住了，
`test_script_parser` 这类纯逻辑测试会需要 Qt 环境。

一句话：**`core` 回答"该怎么处理"，`utils` 回答"怎么拿到"。**
这条判据已经写进两个 `__init__.py` 的 docstring 里。

## 2. 旧爬虫为什么跑不通

```python
url = "https://wiki.kurobbs.com/mc/item/1478089902761410560"   # 单个角色，硬编码
...
page.wait_for_selector("text=基础生命", timeout=20000)
btn_90 = page.locator(".character-tab-item").get_by_text("90", exact=True)
active_panel = page.locator(".skill-introduce-content__item--active")
```

三个问题，每一个都足以让它"看起来跑完了但什么也没抓到"：

1. **只抓一个角色**。没有"遍历所有角色"这一步，自然没法覆盖全量
2. **选择器全靠猜**。`.character-tab-item` / `.skill-introduce-content__item--active`
   在现版本页面里都不存在，全部抛异常被 `except` 吞掉
3. **抓的不是项目要的东西**。`stats_90`（90 级属性）、`skills_lv10`（技能倍率）、
   `resonance_chains`（共鸣链）对"连招提示该按哪个键"没有直接作用

第 2 和第 3 点合起来是最糟的组合：**抓错了东西，还抓不到，而且失败是静默的**。

## 3. 新爬虫

### 3.1 先探结构，不猜

实测确认了两级页面的稳定锚点：

```
列表页  /mc/catalogue/list?fid=1099&sid=1105     （共鸣者分类，65 个）
        a[href*='/item/'] 卡片内：
          .card-footer span              角色名
          [class*='card-star-N']         稀有度（N=4/5）
          .card-skill-attr-icon img      元素（src 里含拼音，如 role-attr-daodian-）

详情页  /mc/item/<id>
        .role-tags .text-ellipsis        形如 "武器：迅刀" / "属性：导电"
        page.title()                     形如 "锁暝-鸣潮WIKI官网-..."
```

**为什么还要进详情页**：列表页没有武器类型，而那是项目最缺的字段。

### 3.2 抓什么

| 数据 | 用途 | 缺了会怎样 |
|---|---|---|
| 角色 → **武器类型** | 生成 `Character_Occupation.txt` | 普攻/重击落不到 `_general/normal_attack/<武器>/` |
| 角色 → 元素 / 稀有度 | 剧本备注、悬浮窗信息 | 无（纯信息） |
| 中文名 ↔ 英文名 | 素材目录用英文名 | 剧本里选不到角色 |

游戏数值不抓。需要的话以后加 `--with-stats`。

### 3.3 工程上的几个决定

- **每抓一个就落盘**。65 个角色要跑 3 分多钟，中断了不能从头再来
- **断点续传**。已在 `characters.json` 里的跳过，`--force` 才重抓
- **随机延时 0.8~1.6s**。固定节奏太像机器人
- **失败重试 2 次**，仍失败就跳过并在日志里点名，不整体崩
- **`--occupation` 是合并不是覆盖**。这条很关键：最初的实现直接重写文件，
  实测把原有 8 条映射冲成了"只有 8 条 + 57 条缺失注释"。
  现在以现有文件为基线，新数据只补/改对得上的条目
- **英文名不确定就留空**。`name_map.json` 里空着的条目是有意的，
  `--occupation` 会在文件末尾点名。猜错会让剧本选到错的素材目录，比留空更难查

## 7. 遗留

- **`Aalto` 没对上中文名**。它是 assets 里唯一有目录但没中文名对应的角色，
  且目录是空的。需要作者确认它是哪个角色（可能是"秋水"）
- **14 个角色缺英文名**：丽贝卡 / 心 / 景燃 / 清宵 / 穗穗 / 绯雪 / 达妮娅 /
  锁暝 / 莉莉 / 洛瑟菈 / 秧秧·玄翎 / 露西 / 西格莉卡 / Aalto。
  这些大多是 3.x 版本新角色，**assets 里本来就没有目录**，
  所以不影响当前使用；要做素材时再补
- **技能描述没抓**。详情页里其实有"最多 3 段""按住普攻"这类文本，
  可以用来推断 `variant` 数量和 `hold` 需求，进而自动生成 `durations_ms` 初值。
  这是下一步最有价值的方向，但要做 tab 切换和文本解析，工作量不小
- **选择器会随 wiki 改版失效**。失效时的表现是"跑完了但字段是空的"，
  所以脚本会统计缺失数并在结尾报告——**如果哪天这个数字突然变大，先怀疑页面改版**
