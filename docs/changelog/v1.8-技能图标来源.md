# v1.8 — 技能图标来源与角色档案

> 一句话：**素材不用手抠了。** 从解包资源镜像批量取游戏原生图标，
> 48 个角色 481 张图，全自动；顺带把角色数据拆成一人一档。

## 触发背景

v1.7 把 wiki 爬虫修好之后，用户提了四个问题：

1. 爬到的内容能不能切割成 `db_西格莉卡.json` 那种一人一档？
2. 技能描述没必要——项目不是做 wiki，只要对应关系和图片
3. wiki 上应该没有"高亮技能图标变化"吧？
4. **图片怎么办，总不能在游戏里一帧一帧截**

第 4 个是真正的痛点：项目已有素材只有 8 个角色 102 张，全是手工裁的，
而 wiki 上的 65 个角色 × 8 类技能 = 500 多张，手工不可能完成。

## 调研：wiki 这条路走不通

先按用户的建议去 wiki 查（用 Playwright 做了实际探测，不是靠猜）。

**结论 1：wiki 上几乎没有技能图标。**

随机抽 12 个角色看详情页：

```
忌炎 千咲 露帕 桃祈 莉莉 心 漂泊者-女-湮灭 椿 清宵 奥古斯塔 折枝 秋水
→ 有技能图标的：0 个
```

唯一例外是锁暝（3.7 新角色），页面里插了 7 个图标。原因是**技能图标是
内联在 wiki 正文富文本里的**（`div.component-content-text` 里手插 `<img>`），
不是结构化的技能面板——编辑者插了就有，没插就没有。

**结论 2：用户的猜测部分正确，但比想象中更彻底。**

用户以为"wiki 只有静态图标，没有高亮/形态变化"。实际情况是连静态的基础技能
图标都基本没有。倒是游戏原生资源里，**每个角色都有多套**（形态变化后的招式
也各有图标），这些 wiki 不展示，但资源包里在。

## 找到真正的来源

顺着 wiki 页面上那些图标的 CDN 域名往上查：

```
https://static.nanoka.cc/assets/ww/UIResources/Common/Atlas/SkillIcon/SkillIconSuoming/SP_IconSuomingY.webp
```

`nanoka.cc` 是社区维护的**鸣潮解包 UI 资源镜像**，路径结构与游戏内完全一致
（`UIResources/Common/Atlas/...`）。同时 GitHub 上也有同源仓库
`TomyJan/WutheringWaves-UIResources`（64GB，分支 3.7）可用于核对目录清单。

规律：

```
{NANOKA}/SkillIcon<拼音代号>/SP_Icon<拼音代号><后缀>.webp
```

- 代号是拼音：`Aimisi`(爱弥斯) `LinNai`(琳奈) `MoNing`(莫宁) `Suoming`(锁暝)
- 后缀按角色不同：忌炎 10 张，爱弥斯 17 张
- 全部 128×128、带 alpha、白色蒙版（游戏运行时按元素色着色）

**踩到的坑**：CDN 对没有 `User-Agent` 的请求返回 403（urllib 默认 UA 为空），
而 `HEAD` 请求也不稳。必须带 UA 且用 GET。

## 后缀含义怎么确定

没有文档，靠交叉验证：

1. 锁暝的 wiki 页面把 7 个图标和技能名对上了
   （`C1`=暝伞形·重锁狱瘴=共鸣解放，`QTE`=拢伞形·闪裂=变奏技能，`T`=伞机鸣动=延奏技能）
2. 拿 6 个角色的同一后缀拼成矩阵看形状
3. 和项目已有手工素材逐张比对

```
A1..A6  技能栏图标 · 常态攻击各段  → normal_attack/normal.png, normal_2.png ...
Y / Y1  共鸣技能                  → resonance_skill/skill.png
C1..C2  共鸣解放                  → resonance_liberation/liberation.png
D1..D2  共鸣回路                  → forte_circuit/forte.png
QTE     变奏技能                  → character/intro.png
T       延奏技能                  → character/outro.png
B1..B6  技能演示图                → 仅当角色没有 A 系列时顶替普攻
```

**`A` 和 `B` 是两种不同性质的图**，这点一开始判断错了：

- `A` = 技能栏图标，简洁的武器形/几何形（爱弥斯的 A1 是剑、A2 是三角带星）
- `B` = 技能演示图，角色动作剪影（wiki 技能介绍里配的那种）

我以为「B 是形态变化招式，都用不上」，但实际检查赞妮时发现她**一个 A 都没有**，
只有 `B1..B5`——她那套就是普攻。所以改成「有 A 用 A，没有 A 用 B 顶」。
这类"某个角色的资源结构和别人不一样"的情况，只有真跑一遍全量才会暴露。

**比对时发现项目原有素材是错的**：`Aemeath/normal_attack/normal.png` 和
`normal_3.png` 是同一张图（斜剑），而 nanoka 的 `A1/A2/A3` 是三张不同的
（斜剑 / 三角带星 / 三角）。说明当初裁图时裁重了。这也是"手工不可靠"的实证。

## 实现

### `tools/factory/icon_fetcher.py`（新）

- 自动探测每个角色实际有哪些后缀（并发 20 路，单角色约 3 秒）
- webp → png（Qt 加载 webp 需要插件，统一转 png 最省事）
- 按 `SUFFIX_MAP` 落到项目目录结构
- **默认不覆盖已有文件**（原因见下）
- `--tint` 按元素色着色，`--overwrite` 才覆盖

**为什么默认不覆盖**：项目早期 8 个角色是手工截图裁的，带游戏内元素光晕，
观感未必更差；更重要的是 `forte_circuit/forte.png` 原本是**能量条截图**
（467×62），语义和技能图标完全不同，盲目覆盖会出问题。
所以第一批测试时被覆盖的 20 个文件，都用 `git checkout --` 恢复了。

### `tools/factory/build_db.py`（新）

把 `characters.json` 拆成 `db/characters/db_<中文名>.json`：

```json
{
  "name": "锁暝", "name_en": "Suoming", "code": "Suoming",
  "rarity": 5,
  "element": {"cn": "导电", "en": "electro"},
  "weapon":  {"cn": "迅刀", "en": "sword"},
  "gender": "女", "birthplace": "梦州",
  "wiki_url": "https://wiki.kurobbs.com/mc/item/...",
  "assets": {
    "normal_attack": ["normal.png", "normal_2.png", "normal_3.png"],
    "resonance_skill": ["skill.png"],
    "resonance_liberation": ["liberation.png", "liberation_2.png"],
    "character": ["intro.png", "outro.png"],
    "forte_circuit": ["forte.png", "forte_2.png"]
  },
  "asset_source": "nanoka",
  "scraped_at": "2026-10-25T05:36:54"
}
```

`assets` 是**实际扫目录**得到的，缺的槽位不出现——所以这个文件同时也是
素材完整性清单。`asset_source` 按"128×128 且带 alpha = nanoka，否则 manual"
判定，一眼能看出哪些角色还在用旧素材。

**不抓技能描述**，理由和 v1.7 一样：那是 wiki 的活，对"下一步按哪个键"没帮助。

## 顺手修的两个真 bug

### 1. 技能图标的查找关键字写错了

`config.json` 里 `assets.default_filename.skill = "normal"`，但
`resonance_skill/` 目录里的文件叫 `skill.png`——关键字永远匹配不上，
每次都退到"取目录里第一张"。图片碰巧是对的，但属于运气不是规则。

改成 `skill`。`execution` 同样（它映射到 `resonance_skill` 目录）。
改完以后所有槽位都是 `exclusive:keyword`（最理想来源），不再是 `exclusive:first`。

### 2. 重击格的按键图标是空的

`get_button_path("heavy")` 去 `keymaps` 里找 `heavy`，但 keymaps 只有 `basic`
（游戏里重击和普攻共用攻击键）。结果提示"重击"却不告诉你按哪个键。

加了 `KEY_FAMILY = {"heavy": "basic"}` 回退。

## 数据

```
素材         102 张 → 481 张（6.5 MB）
有素材角色     8 个 → 48 个
最大单角色    12 张（陆·赫斯）
```

完整下载耗时约 3 分 20 秒（50 个角色，含重跑）。

## 遗留

- **`B` 系列对多数角色仍不入库**。它们是技能演示图，只有当角色没有 A 系列时才拿来
  顶普攻（赞妮就是这种情况）。另外"形态变化后的招式"（锁暝「念深状态」下普攻
  替换成"普攻·解伞形"）也会占用 A/B 编号，当前判定逻辑按不到这么细。
- **17 个角色仍无素材**：丹瑾、卜灵、桃祈、洛瑟菈、露西（代号对不上资源目录），
  漂泊者 × 8（`Zhujue*` / `Vision*` 多形态，需手工指定）。都不影响当前剧本。
- **角色头像还没接**。`character/avatar.png` 仍是手工截图，nanoka 只镜像技能图标。
  备选：GitHub 的 `IconRoleHeadCircle256`（152 张，但文件名是数字 ID，需要 ID 映射表）。
- **`--tint` 是逐像素 Python 循环**，单张约 0.15 秒。全量着色要 1 分多钟，
  真要常用应该换成 NumPy 向量化。
- **`normal_2.png` 不是每个角色都有**。有些角色只出 A1 没有 A2，普攻第二段会
  降级到 `normal.png`。这是资源本身的缺口，不是工具漏抓。
