# docs/ — 文档

两类东西，用途完全不同：

```
docs/
├── README.md              本文件
├── changelog/             AI 参与的改动记录（历史，只增不改）
│   ├── README.md          索引 + 编写规范
│   ├── v1.1-性能与稳定.md
│   ├── v1.2-长短按判定.md
│   ├── v1.3-时间轴引擎.md
│   ├── v1.4-同键缓冲规则.md
│   └── v1.5-解析器分层与体检.md
├── gaps-assessment.md     项目缺口评估与路线图（活文档，会更新）
└── demo_v1/               演示截图与录像
```

## changelog/ vs gaps-assessment.md

| | `changelog/` | `gaps-assessment.md` |
|---|---|---|
| 性质 | **已发生的事实** | **还没做的事** |
| 更新方式 | 只增不改，写错了新开一份 | 随进度更新状态 |
| 读它的时机 | "这行为什么是这样" | "下一步该做什么" |
| 单位 | 一次可交付的改动 | 一个能力缺口 |

`changelog/` 的每份记录有固定的六段：**背景 / 根因 / 改法 / 文件清单 / 验证 / 遗留风险**。
其中"根因"要求贴关键代码行，"验证"要求给得出具体数字——不能写"感觉快了很多"。

## demo_v1/

v1.0 的演示素材。文件名里的 `v1` 指的是**版本**，不是 changelog 的第一个条目。

## 写文档的原则

1. **代码是事实，文档是解释**。文档里的路径、字段名必须能在代码里搜到。
2. **不留过期的断言**。改了代码发现文档对不上，要么改文档，要么在文档里标注"已过期"。
   `gaps-assessment.md` 里的条目带 ✅/⬜ 状态就是这个原因。
3. **不要为每个目录都写 README**。README 应该出现在"有人要遵守约定"的地方
   （`assets/` 有命名约定、`configs/` 有格式约定、`tools/` 有归属约定）。
   纯代码包（`core/` `ui/` `utils/`）的说明写在 `__init__.py` 的 docstring 里——
   IDE 能看到，`help()` 能查，也不会和代码脱节。
