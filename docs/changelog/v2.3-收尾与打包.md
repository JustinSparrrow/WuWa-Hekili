# v2.3 收尾：README 重写 + 打包脚本重构 + 发布版专属问题修复

## 背景 / 触发

作者原话：

> ok那就可以收尾了。更新根目录的README，重构一下build.rat，生成新一版的。然后帮我提交推送一下GitHub

在上一轮（v2.2 素材工坊）之后，功能已经到达作者认可的状态。这一轮不再加功能，
只做「让它能体面发出去」的事：文档说真话、打包可复现、发布版不在别人机器上崩。

顺带在打包时发现了三个**只在打包后才发作**的问题，都是真 bug，不是美化。

## 根因

### 1. 日志目录在打包后指向错误位置

```python
# utils/logger.py（改前）
log_dir = os.path.join(os.path.dirname(os.path.dirname(os.path.abspath(__file__))), "logs")
```

注释写着"打包后位于 exe 同级目录"，实际不是。PyInstaller 把模块放进
`_internal/`，所以 `dirname(dirname(__file__))` 得到的是 `_internal`，
日志落在 `_internal/logs/` —— 玩家永远找不到，日志等于白记。

### 2. windowed 打包后 `print()` 会抛异常

PyInstaller 以 `-w`（windowed，不弹控制台）打包后，
`sys.stdout` / `sys.stderr` 都是 `None`，
任何一句 `print()` 都会 `AttributeError: 'NoneType' object has no attribute 'write'`。

而项目里的裸 `print` 恰好都在**最不该崩的路径**上：

| 位置 | 什么时候触发 |
|---|---|
| `config_manager` 生成默认配置 | **首次运行必触发** |
| `config_manager` 配置损坏 / 保存失败 | 配置出问题时 |
| `settings_window` 保存按键映射 | 用户点「保存并应用」时 |

也就是说：发给别人的第一版，很可能双击就闪退，或者改完按键设置闪退。

### 3. `logging.StreamHandler` 在无 stderr 时刷错误

`StreamHandler` 绑定的是 import 时的 `sys.stderr`（`None`），
之后每次 `log.info()` 都会走 logging 的错误分支，往不存在的地方写
"--- Logging error ---"。

### 4. 编辑器保存的剧本和读取端不是同一个目录

```python
# ui/routine_uploader.py（改前）
base_dir = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
routines_dir = os.path.join(base_dir, "configs", "routines")
```

开发环境里这行和 `project_root()` 恰好得到同一个目录，所以一直没暴露。
打包后 `__file__` 在 `_internal/ui/` 下，算出来的却是 exe 同级 —— 但**纯属巧合**；
一旦 PyInstaller 改了布局（或改成 onefile），保存成功但列表里看不到。

读取端（`start_menu.recent_routine` / `routine_selector`）都已经用
`project_root()`，只有保存这一处是手算的。

### 5. `.gitignore` 把 `build.bat` 和 `tools/build/` 一起忽略了

```gitignore
build/
build.bat
```

`build/` 在 gitignore 里会匹配**任意层级**名为 build 的目录，
于是新加的源码目录 `tools/build/` 也被静默忽略，`git add -A` 根本加不进去。

## 改法

### `build.bat` 重写

原来的 5 步流程保留，但补上了「出错要停」和「资源要放对」：

| 改进 | 原因 |
|---|---|
| 版本号单点 | 目录名 / zip 名 / exe 属性里的版本号都从 `set VERSION=` 推 |
| **打包前跑 89 项测试** | 测试不过就不出包，避免把坏版本发出去 |
| 用 `--add-data` 直接打进资源 | 原来是先打包再用 `xcopy` 往 `_internal` 里塞，绕了一圈且容易漏 |
| 组装后**自检 5 处关键文件** | 打包最常见的翻车是"资源没进包，运行时才炸" |
| 压缩改用 `tools/build/make_zip.py` | 见下方「为什么不用系统压缩命令」 |
| 支持 `--no-zip` / `--keep-temp` | 排查时不想每次都重新压 107MB |
| 支持 `PYTHON_EXE` | 机器上有多个 Python 时不用改脚本 |
| 存成 **GBK** | 中文 Windows 的 cmd 用 936 解析批处理，UTF-8 会把注释解析成命令 |

> **不再单独打包 `AssetFactory.exe`。** 素材工坊在 v2.2 已经是主菜单第四个入口，
> 再出一个独立 exe 只会让人以为要装两个东西。

### 为什么不用系统压缩命令

第一次跑打包，前 5 步全绿，最后一步报：

```
文件 api-ms-win-core-debug-l1-1-0.dll 正由另一进程使用
```

原因是刚生成的 dll 被 Windows Defender 短暂扫了一遍。系统压缩命令（PowerShell
的 `Compress-Archive`）遇到这种情况会**整体失败**，而它的退出码仍然是 0 ——
bat 无从判断，于是"打包成功"的横幅照打，zip 根本没生成。

`make_zip.py` 改成逐文件写、占用就退避重试 4 次；仍然失败则记录跳过清单，
并且**只要跳过的是 dll/pyd 就返回失败**（少了 dll 的包等于发了个跑不起来的包）。
实测 900 个文件全部写入，106.9 MB。

### 三个运行时修复

- `utils/logger.py`：日志目录改用 `project_root()`；`sys.stderr is None` 时不挂
  `StreamHandler`
- `utils/config_manager.py`：4 处 `print` 换成 `log.*`
- `ui/settings_window.py`：保存成功那句 `print` 换成 `log.info`
- `main.py`：入口最前面加 `_ensure_std_streams()`，打包环境下把 `None` 的
  stdout/stderr 指向 `os.devnull`，兜住任何漏网的 `print`

最后这条是保险：改完已知的 print 之后不一定就没有了，而**一句漏网的 print
就足以让发布版闪退**，代价又极低。

### `requirements.txt`

原 `requirement.txt`（单数）有三个包名/版本是错的，照着装会失败：

| 原来 | 问题 |
|---|---|
| `pyside==6.10.1` | 包名是 `PySide6`；`pyside` 是 Qt5 时代的老包，PyPI 上指向 1.x |
| `shiboken6==6.10` | 版本号不完整，应为 `6.10.1` |
| `opencv-python==4.13` | 发布号需要四段，实际是 `4.13.0.90` |
| 缺 `keyboard` / `mouse` | 这两个是核心依赖，代码里直接 import |

改成范围约束 + 注释里标注实测版本，并把文件改名为 `requirements.txt`（复数，
pip 的通行写法）。同时把 Python 下限提到 **3.11**——numpy 2.x 从 3.11 起才有 wheel，
原来 README 写的 3.8 根本装不上。

## 遗留 / 风险

- **exe 只验证了生成，没有在干净机器上双击运行过。** 严格来说发布前应该在
  没有 Python 环境的机器上试一次；本轮受限于环境，只做了文件级自检。
- `--exclude-module` 排除了 QtWebEngine / Qt3D / QtMultimedia，目前代码不用它们；
  将来若引入会打包成功但运行时报缺失，需要同步删掉对应的 exclude。
- 体积 266 MB 主要是 Qt 与 OpenCV 的 dll，属正常量级。若想再压，可以试 UPX，
  但 PyInstaller + UPX 对 Qt dll 有兼容风险，本轮未做。
- `docs/ui/*.png` 仍不入库，README 里没有引用这些截图（避免链接失效）。
