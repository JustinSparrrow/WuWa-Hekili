# v1.1 — 内存与流畅度优化

- **日期**：2026-10-25
- **触发**：作者要求在"能正常运行"的前提下降低内存占用、提升流畅度，并补充注释
- **性质**：纯重构 + 性能优化，**不改变任何外部行为**（手感、判定规则、界面布局全部保持）

## 1. 背景

v1.0 能跑，但有三类问题：

| 现象 | 严重度 |
|---|---|
| 连招按得快时内存一路涨 | 高（真实泄漏） |
| 每次推进都扫磁盘 + 解码 PNG | 高（卡顿来源） |
| 输入线程 200Hz 空转 | 中（CPU 占用） |
| 启动时要构造 4 个窗口，其中编辑器扫 46 个角色目录 | 中（启动慢） |

## 2. 根因

### 2.1 动画对象泄漏（最严重）

`overlay_window._slide()` 每推进一格就 `new` 一个 `QParallelAnimationGroup` + 10 个
`QPropertyAnimation`，旧组直接覆盖引用。但这些对象的 parent 是窗口，**不会被 GC**，
于是每按一次键就永久留下 11 个 QObject。

连招 200 次 = 2200 个对象，内存与 `children()` 列表一起涨。

### 2.2 格子反复构造销毁

飞出去的格子调 `deleteLater()`，新格子重新 `new`。`deleteLater` 依赖事件循环，
在 `processEvents` 阶段回收不及时；且每次构造都要重载图、重解析 QSS。

### 2.3 图标路径每次重算

`AssetManager.get_icon_path()` 每次调用都要 `os.listdir` 逐层找文件，
一级降级失败就再扫一遍，最坏 8~12 次目录遍历。而悬浮窗每次刷新要算 4 个槽位。

### 2.4 每次按键都写盘

`config.update_setting()` 每次调用都完整 `json.dump` 一遍 config.json。
拖窗口时 `mouseMoveEvent` 每移动 1px 就写一次。

## 3. 改法

### 3.1 动画对象常驻复用

改成 **5 组动画实例常驻**，每轮只改 `targetObject` / `startValue` / `endValue`：

```python
# 初始化时建好，之后永远不 new
self._anim_groups = [QParallelAnimationGroup(self) for _ in range(self.SLOT_COUNT + 1)]
```

> 一开始试过 `deleteLater()` + 重建，实测在 `processEvents` 循环里对象数仍会增长
> （回收滞后）。**常驻复用才是唯一稳定的解**，不是"记得 delete"。

### 3.2 格子池

飞出的格子回收进 `self._pool`，下一轮 `_take_widget()` 直接取出来改数据。

### 3.3 路径缓存 + 图片缓存

- `AssetManager`：`self._path_cache` 字典，key 是 `(角色, 类型, 变体, force_general, custom_icon)`
- `widgets.py`：模块级 `QPixmap` 缓存，上限 300 张（超出直接丢弃，不 LRU）

### 3.4 输入轮询降频

`POLL_INTERVAL_MS`：5ms（200Hz）→ 10ms（100Hz）。游戏 60fps 下 16.7ms 一帧，
100Hz 已有 1.67 倍余量。

### 3.5 启动懒加载

`main.py` 拆出 `_get_settings_win()` / `_get_uploader_win()` / `_get_selector_win()`，
点开才构造。启动阶段只保留主菜单。

## 4. 顺手修掉的 5 个 bug

| Bug | 根因 |
|---|---|
| 历史槽切人图标显示错角色 | `get_visual_data()` 注释写着"显示切过去的目标角色"，代码用的是切换**前**的 `h_char` |
| 启动绿框永久残留 | `set_activated_style()` 绕过样式缓存直接改 QSS，但没清 `_style_key`，下一次 `update_style()` 误判"样式没变"而跳过 |
| 手柄十字键映射失效 | 代码读 `controller.hats`，`config.json` 里的键名是 `hat_`，一直靠兜底的字符串比对勉强生效 |
| 退出时误伤其它程序的全局钩子 | 用了 `keyboard.unhook_all()`，改成 `unhook(handle)` |
| 设置窗保存会覆盖已丢失的绑定 | 配置里的图标若从 `assets/ui/` 删了，下拉框落到首项，一保存就被改掉。改成把孤儿值插回选项列表 |

关键数字：

| 指标 | v1.0 | v1.1 |
|---|---|---|
| 图标路径解析 | 0.67 ms/次（每次扫 8~12 次目录） | **0.03 ms/次（≈24×）** |
| PNG 解码 | 每次 `set_data` 都解 | 缓存命中即复用 |
| 200 次推进后动画对象 | 2200+ 持续增长 | **恒定 10** |
| 200 次推进后槽位 | 不断新建 | **恒定 4，空闲池 ≤1** |
| 启动构造 | 4 个窗口（含扫 46 个目录） | 只建主菜单，编辑器 8.3ms 移出启动路径 |

## 7. 遗留 / 风险

- **故意没做实装 `heavy_hold_time`**：长按判定属于新增功能，会改变手感，留给 v1.2。
- **故意没改"松手才推进"**：这是为合轴/预输入留的设计空间，动它会动到核心体验。
- 动画时长从 250ms 调到 200ms（更跟手），这是一处**有感知的行为变化**。
  想改回来：`ui/overlay_window.py` 的 `HekiliOverlay.ANIM_MS`。
- QPixmap 缓存上限 300 是拍脑袋定的，没有做命中率统计。
  如果以后角色/变体数量暴涨，可能需要换成按角色分桶 + LRU。
