# v2.1 — 双主题：夜间 / 日间

> 一句话：**同一套界面，两套配色。** 夜间是原来的墨黑玻璃 + 香槟金，
> 日间是冷灰蓝白玻璃 + 钢蓝，在「按键设置」顶部一键切，立刻生效、写进配置。

## 触发背景

v2.0 交付后作者反馈：

> 颜色的话可以的话做个夜间模式，目前的颜色就夜间模式，日间模式就用你说的冷灰蓝，
> 白色系的吧，我比较喜欢，然后可以自己选择是否开夜间模式。

要点三条：
1. 现有配色保留，命名为**夜间**
2. 新增**日间**：冷灰蓝 + 白色系
3. **可以自己选**

## 根因：颜色散落在模块级常量里

v2.0 的 `theme.py` 是这样的：

```python
GOLD = "#E8C88C"
IVORY = "#F6F2E9"
...
```

而各窗口是 `from ui.theme import GOLD, IVORY` 这样导入的。
Python 的 `from ... import` **在 import 那一刻就把值拷走了**，
之后不管 `theme` 里的常量怎么改，别处拿到的都是旧值。

所以想切换主题，必须先解决"颜色值怎么被读到"这件事。

## 改法

### 1. 调色板 + 运行时刷全局

```python
DARK  = {"GOLD": "#E8C88C", "IVORY": "#F6F2E9", ...}
LIGHT = {"GOLD": "#3E6FA3", "IVORY": "#1C2530", ...}

def apply(mode):
    MODE = mode
    for k, v in PALETTES[mode].items():
        globals()[k] = v          # 把选中的调色板刷进模块全局
    _generation += 1
    bus.changed.emit()
```

配套的硬约束写进了 `theme.py` 的头注释：

> **所有颜色都必须走模块属性**（`theme.GOLD`），不要 `from ui.theme import GOLD`

六个 ui 文件里的 74 处常量引用全部改成了 `theme.XXX`。
（改的时候踩了个坑：正则把 QSS 里的 `font-size` 也改成了 `theme.font-size`，
以及把菜单样式里的 `rgba(...)` 改成了 `theme.rgba(...)`——两者都在字符串里。
后来统一修回来，并把那段 QSS 直接抽成了 `theme.menu_qss()`。）

### 2. 缓存失效靠"代数"

玻璃面板是缓存成 QPixmap 的（v2.0 的性能设计），切主题时不清缓存就会留着旧配色。

没有做"遍历所有窗口挨个通知"，而是给主题一个自增的**代数**：

```python
theme.generation()          # 每次 apply 就 +1
...
if self._plate is None or self._theme_gen != theme.generation():
    self._build_plate()     # 只有真正过期了才重建
```

窗口什么都不用管，只要在 `paintEvent` 里比一下代数。
再加一个 `theme.bus.changed` 信号，让 `GlassWindow` 顺手把控件皮肤（QSS）也换掉。

### 3. 不止是换颜色

白色系有几个"直接换色就会坏"的地方，逐个处理：

| 位置 | 问题 | 处理 |
|---|---|---|
| 按键图标 | 素材是"白色字形 + 透明底"，贴到白底上直接消失 | 永远垫一块深色键帽底板（`KEYCAP_BG`），两种主题都更像真按键 |
| 柔光 | 白底会"吃掉"光晕，30% 和 90% 的进度看起来一样 | 日间把柔光透明度 ×1.7 |
| 玻璃内描边 | 白卡片描白边 = 没有边 | 日间下缘改用灰蓝描边 |
| 顶部反光 | 白底上的白高光看不见 | 日间换成钢蓝反光 |
| 元素色 | 浅色元素（衍射 #FFD36E）在白底上几乎不可见 | 六元素各准备一深一浅两套 |
| 金属描边 | 原本写死金色明暗，琥珀/青色的描边会冷热混色变脏 | 改成从当前色自己推 `lighter/darker` |

### 4. 放在哪儿切

放在**按键设置窗**最上面，做成分段控件「外观：夜间 / 日间」。

- 切完立刻生效，**不用点"保存并应用"** —— 外观是随手试的东西
- 同时写进 `config.json` 的 `settings.theme`（这个字段 v1.0 就有，正好复用）
- 启动时 `main.py` 读一次，恢复上次的选择

## 验证

- 三套回归测试全绿：42 + 40 + 7
- 双主题冒烟：6 个窗口 × 2 套主题，全部构造 + 渲染通过
- **运行中切换**：先建成试过的窗口，再 `apply("light")`，检查
  - 所有 `GlassWindow._plate` 被清空（下次绘制重建）
  - 主题代数从 0 → 1 → 2 正确递增
  - 渲染结果确实变成浅色（见 `_sw_*` 临时图，已清理）
- 视觉：`python tools/preview_ui.py --shot --theme light`

## 遗留 / 风险

| 问题 | 说明 |
|---|---|
| 浅色悬浮窗打游戏不实用 | 白光面板压在战斗特效上会抢视线，夜间仍是实战推荐项；日间更适合录制/桌面调试 |
| `QMessageBox` / `QInputDialog` 未跟随 | 仍是系统原生样式，浅色下反而不违和，深色下略跳 |
| 强调色语义 | 日间把"金"换成了"钢蓝"，如果之后想让日间也保留香槟金，改 `LIGHT["GOLD"]` 一处即可（但白底上对比会偏弱） |
| 头像裁切 | 与主题无关，仍是 v2.0 的老问题 |
