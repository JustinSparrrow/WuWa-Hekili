# WuWa_Hekili · 鸣潮连招提示器

一个给《鸣潮》用的 [Hekili](https://www.curseforge.com/wow/addons/hekili) 式悬浮窗：
它不替你按键，只在屏幕上告诉你**下一步该按哪个键、现在能不能按**。

**⚠️ 安全声明**：本工具只监听键鼠/手柄信号，**不读取、不修改、不注入游戏进程**，属于绿色辅助。
但任何覆盖层工具在反作弊系统下都存在理论上的误判风险，请自行评估后再使用。

当前版本 **v2.3**。

---

## 它解决什么问题

视频攻略能告诉你"这一套轴是什么"，但没法告诉你"你刚才那一下按早了 80 毫秒"。
动作游戏里，"我按了键"和"角色打出动作"从来不是同一件事——角色有前摇、判定、后摇，
动作播完之前游戏要么把输入暂存、要么直接丢弃。

v1.0 把按键事件直接当成"动作完成"，于是有三个错位：

| 现象 | v1.0 的行为 | 原因 |
|---|---|---|
| 连按跑飞 | 点 5 下推 5 格 | 动画期间游戏只认 1~2 下，程序却每下都算 |
| 预输入空转 | 按早了也推进 | 游戏把太早的输入丢了，程序在自说自话 |
| 双键并行 | 做不到 | 线性链表只能表达"同一时刻只有一件事" |

现在的做法是给按键加一个**和游戏时间线对齐的模型**（见下文「时间轴」），
不需要知道任何游戏内部状态。

## 核心特性

- **悬浮窗**：一整块胶囊面板，左边常驻角色头像 + 元素徽记，右边四格时间轴，
  最右侧是「启动轴 24/49 / 切 · 琳奈 / 长按 0.5s」这类当前状态。
  面板、连续曲率圆角、阴影、玻璃噪点、金色描边全部 QPainter 自绘。
- **夜间 / 日间双主题**：夜间是墨黑玻璃 + 香槟金（打游戏用），
  日间是冷灰蓝白玻璃 + 钢蓝（录制、桌面调轴用）。设置窗顶部一键切换，立刻生效。
- **长短按区分**：普攻与重击共用一个攻击键，按**按住时长**区分，
  判定在松手瞬间完成，零待机开销。
- **时间轴**：预输入缓冲、连按合并、蓄力中并行插入、环形进度。
- **双轴支持**：自动区分「启动轴 (Opener)」与「循环轴 (Loop)」，启动完无缝进循环。
- **剧本语法**：一套「黑话」字符串写轴，带行列号诊断，可反向序列化。
- **素材工坊**：自己录了像就自己补素材——主菜单第四个入口，
  打开录像、框 8 个区域、停在关键帧按 `1`~`8`，自动裁切入库。
- **自带素材**：481 张技能图标 / 56 个角色目录 / 65 个角色档案（元素、武器、星级）。

## 快速开始

### 方式一：用发布包（推荐）

1. 解压 `WuWa_Hekili_v2.3_win64.zip`
2. 运行 `WuWa_Hekili.exe`（会请求管理员权限，**必须同意**）
3. 首次运行会在 exe 旁边生成 `config.json`

### 方式二：从源码运行

要求 **Windows 10/11** + **Python 3.11+**（numpy 2.x 需要 3.11 起才有 wheel）。

```bash
git clone https://github.com/JustinSparrrow/WuWa-Hekili.git
cd WuWa-Hekili
pip install -r requirements.txt
python main.py   # 需要管理员权限，见下
```

> **为什么要管理员权限**：鸣潮客户端（含 ACE 反作弊）通常以高权限运行，
> 普通权限下的底层键盘钩子在游戏处于前台时收不到消息。
> 命令行启动请用「终端(管理员)」；用 VS Code / PyCharm 时也要让编辑器以管理员身份运行。

### 游戏内设置

显示模式必须改成 **无边框窗口** 或 **窗口化**。独占全屏下 Windows 无法在其他程序上渲染覆盖层。

## 写一条轴（黑话语法）

主菜单 →「流程上传」，直接写字符串，点「解析并预览图标」。

| 写法 | 含义 |
|---|---|
| `a` `e` `r` `q` `z` `f` `s` `j` | 普攻 / 技能 / 解放 / 声骸 / 重击 / 处决 / 闪避 / 跳跃 |
| `跳` `闪` | 中文写法，等同 `j` / `s` |
| `a2` `e3` | 变体（二段普攻、技能三段），只影响图标匹配，不影响判定 |
| `e+` `e3+` | **长按**：必须按住够久才算这一下 |
| `爱` `忌` `莫` | 切人（写角色英文名或自己在队伍里设的代称） |
| `(变奏)角色名` | 变奏切入，显示成「变奏-角色名」 |
| `// 注释` `/* 块注释 */` | 写轴时做标注 |
| `a*3` | 重复三次，等价 `aaa` |
| `z&q` | `q` 与前面的 `z` **并行**（给 `q` 打上 `parallel: true`） |
| `r!` | 不可打断（`uncancellable: true`），换键也要等它播完 |
| `a{620}` | 这一步占位 620ms（`duration_ms`） |

修饰符顺序不限，`e3+` 和 `e+3` 都认；同一修饰符写两次会出 W002 警告。
`&` 不是修饰符而是独立记号，它把**后面那个**动作标记为可并行。

解析器会报出带行列号的诊断。认识的字符之外的东西不会静默消失——旧版
`re.findall` 会把它吃掉，现在会明确告诉你「第 1 行第 12 个字符认不出来」。

### 判定规则（决定"轻按 / 长按"怎么算）

| 动作类型 | 要求 |
|---|---|
| `basic` 普攻 | 轻按（时长 < 阈值）|
| `heavy` 重击 | 长按（时长 ≥ 阈值）|
| `intro` / `dodge` / `jump` | 按下即推进，不看时长 |
| `skill` / `ult` / `echo` / `execution` | 默认不看时长；写了 `+`（JSON 里的 `"hold": true`）才要求长按 |

## 时间轴

```
剧本指针   当前该做哪一步
时间闸门   同一颗键的"冷却"到什么时候
输入缓冲   闸门关着时收到的、键名正确的输入先存着
并行集合   已经被"提前完成"的未来步
```

一次按键的旅程：

```
松手 ──> 键名对得上当前步？
          ├─ 手势（轻按/长按）也对
          │    ├─ 闸门已开  -> 直接推进
          │    └─ 闸门未开  -> 压进缓冲，等闸门开（预输入）
          └─ 对不上当前步 -> 蓄力中允许插入的动作？是就提前完成它
```

### 闸门只在"连续按同一颗键"时关

鸣潮里新动作的优先级很高——**普攻还没打完就按技能，技能会直接打断普攻放出来**，
闪避更能取消一切。所以"要等动作播完"这件事只对**同一颗键连点**成立。

| 情况 | 例子 | 是否关闸 |
|---|---|---|
| 下一步还是同一颗键 | `a → a`、`a → z`（共用攻击键） | **关**，等动作播完 |
| 换了一颗键 | `a → e`、`r → a`、`a → 闪` | **不关**，立刻推进 |
| 显式声明不可打断 | `{"type":"ult","uncancellable":true}` | **关**，即使换键也等 |

也就是说：**跨键连打不需要缓冲，程序不该拦**。

- **预输入**：只用在同键连段上。缓冲项有寿命（`input_buffer_ms`），超时说明按得太早、
  游戏早就丢了，那就**不推进**，提示留在原格等你重按。
- **连按**：同一动作的重复输入在缓冲里合并成一条并刷新时间戳。狂按 5 下只推进 1 格。
- **并行**：当前步是长按类动作，且后面某一步声明了并行时，屏幕上方浮出一个小窗
  「并行轨 · 可同时」。直接按它就提前完成那一步，主指针等你松手完成重击后才跳过它。

> **并行必须剧本显式声明，不按动作类型自动放行。**
> 原因很实际：「蓄力中放声骸」是**角色特性**——琳奈可以，莫宁和爱弥斯在同样的位置就不行。
> 按类型自动放行会让不该并行的角色被提前消耗一步。

> **第二条时间轴是按需启用的**：加载剧本先扫一遍，整个剧本没有任何并行点就完全不创建
> 小窗（日志写「剧本无并行动作，跳过第二条时间轴」），普通轴零额外开销。

## 配置文件

`config.json` 在项目根（打包后在 exe 旁边），首次运行自动生成。**不入版本库**——
每个人的按键映射、窗口位置、手感参数都不一样。

```jsonc
{
  "settings": {
    "current_device": "xbox",   // "xbox" / "keyboard"
    "theme": "dark",            // "dark" / "light"
    "window_opacity": 0.9,
    "heavy_hold_time": 0.5,     // 长按阈值(秒)
    "strict_tap_check": true    // 期望普攻时，按住太久是否判为打出重击
  },
  "timing": {
    "enabled": true,            // 总开关。false 退化成"按一下就推一格"
    "input_buffer_ms": 250,     // 预输入寿命
    "enable_parallel": true,
    "auto_parallel": [],        // 全局允许并行的组合；默认空，靠剧本写
    "durations_ms": {           // 每类动作的占位时长（手感参数，不是游戏数据）
      "basic": 290, "heavy": 700, "skill": 520, "ult": 1100,
      "echo": 520, "execution": 600, "dodge": 320, "jump": 280, "intro": 500
    },
    "character_durations": {    // 角色级覆盖，只写和全局不一样的
      "Lynae": { "heavy": 780 }
    }
  },
  "controller": { "buttons": {}, "axes": {}, "hat_": {} },
  "assets": { "folder_mapping": {}, "default_filename": {} },
  "keymaps": { "xbox": {}, "keyboard": {} }
}
```

时长优先级：**剧本单步 `duration_ms` > `character_durations` > `durations_ms`**。

> **`durations_ms` 只影响"同键连打"。** 换键的步子在 v1.3 之后完全不看这张表
> （游戏会让新动作直接打断旧动作）。所以基本只需要调 `basic`——它就是
> "一段普攻占多久"。提示**慢半拍**就调小，**抢在角色前面**就调大。
> 只有声明了 `"uncancellable": true` 的动作才会让别的键也等。

### 怎么把时长调到准

1. 把 `timing.enabled` 改成 `false`，正常打两三局。
2. 关掉悬浮窗时，日志里会打一行 `[Timing] 本局观测到的动作节奏(毫秒)`。
3. 把数字填回 `durations_ms`，再把 `enabled` 打开。

关闭时间轴时的间隔就是你的自然节奏，虽然混了反应时间，但比凭空猜准得多。

## 素材

素材按「**默认通用、按需专属**」取舍，判据是「这张图会随角色变化吗」：

- 普攻 / 重击按武器类型落到 `_general`（单手剑、迅刀、长刃……）
- 技能 / 解放 / 头像 / 回路**必须专属**
- 声骸 / 跳跃 / 闪避 / 协奏值**通用**

图标来源是社区的解包镜像（`static.nanoka.cc`），批量下载见
`python tools/factory/icon_fetcher.py`。自己录了像想补素材，用主菜单的「素材工坊」。

查找是三级降级：角色专属 → 关键字匹配（`normal_2` / `skill_3` 这类）→ 通用。
`tools/checks/routine_lint.py` 能打印每一步素材到底从哪来（`explain_icon_path`）。

## 为什么不做这些（已验证过，不是没想到）

| 方案 | 结论 |
|---|---|
| 读游戏内存 | **不要用。** 腾讯 ACE 内核级反作弊会检测内存读取与进程注入，还会做"技能释放间隔是否符合动画帧率"的行为分析，用户协议也明确保留扫描内存与封禁的权利 |
| 官方插件接口 | **不存在。** 库洛只开放账号侧的 HTTP 接口（抽卡记录一类），没有实时战斗状态接口，做不了 WoW 那种官方 Addon |
| 屏幕识别读资源条 | 可行。实测协奏圈 / 回路条 / 大招能量都在 HUD 固定位置，不需要 OCR 只需数亮点。但收益主要在"自动排轴"，离提示器本职较远，暂未做 |
| 分角色伤害统计 | **做不出来，且不是精度问题。** 伤害数字浮在**怪身上**，声骸技能、延奏增伤、协同攻击都属于后台伤害，无法归因到具体角色。魔兽能做是因为战斗日志直接给 `source`，鸣潮没有等价物——给错的数字比不给更伤信任 |
| 队伍总伤害 | 可做。Boss 血条位置固定、极干净，数亮像素即可。但只有百分比，且要先做一次 ROI 标定 |

## 关于"要不要给每个角色写一个类"

不需要。判断标准只有一条：**差异是"数值不同"还是"规则不同"？**

- "琳奈的重击比爱弥斯长 80ms" → 数值不同 → 填 `character_durations`，不写代码
- "某个角色的形态切换会重置普攻段数" → 规则不同 → 才值得加一个可选 hook

鸣潮角色的差异绝大部分在**数据维度**（时长、段数、能否并行），按大类继承只能覆盖
"法师/近战"这种粗粒度，而逐个写子类会得到一堆只改一个数字的三行类。
详见 [docs/changelog](docs/changelog/README.md)。

## 路线图

- **时长自标定**：现在 `durations_ms` 靠手填。可以做"学习模式"——闸门关闭时记录
  每类动作的自然间隔，自动写回配置。这是所有后续功能的基准。
- **角色 profile 文件化**：`character_durations` 现在是扁平表，条目多了可以改成
  `profiles/<角色>.json`，一个文件装"时长 + 并行关系 + 机制开关"，方便社区贡献。
- **轴效率对比**：Boss 血条 ROI + 计时，得出"削血% ÷ 用时"，用来比较两套轴谁更好。
  比 DPS 榜现实得多，因为它不需要归因。
- **打错复盘**：`Director` 现在遇到"按错键"是静默忽略的。把这一步说出来 +
  记录到复盘日志，就能从"提示器"变成"教练"。
